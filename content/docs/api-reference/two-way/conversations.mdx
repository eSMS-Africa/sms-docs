---
title: Conversations
description: One thread per phone per keyword - list conversations with unread counts and the conversation-affinity window, read a thread, and mark it read.
---

A **conversation** is the thread between one phone and one of your keywords on one short
code. It is created the first time either side messages the other, and its
`conversation_id` is the same ID you get in every
[`message.inbound` webhook](/docs/api-reference/two-way/webhooks#messageinbound) and
send response, so you can key your own session state on it.

Each conversation also shows the **affinity window**: while `affinity_active` is `true`,
plain replies from that phone on a shared code (no keyword) are delivered to you. The
window runs for 72 hours (by default) from the last message your keyword sent to the phone.
If another keyword on the same code texts that phone more recently, plain replies go to it
instead, even though your window has not expired.

All conversation endpoints need `service_id` or `keyword` (plus `code` if you hold the
keyword on two codes). Scope: `two_way` or `query`.

## List conversations

```
GET https://sms.esmsafrica.io/v1/two-way/conversations
```

Most recent activity first, [cursor paginated](/docs/api-reference/two-way#pagination).

| Parameter | Type | Description |
|-----------|------|-------------|
| `service_id` / `keyword` | integer / string | Required: which keyword. |
| `code` | string | With `keyword`, when you hold it on two codes. |
| `unread_only` | boolean | Only conversations with unread inbound messages. |
| `cursor` | string | `next_cursor` from the previous page. |
| `limit` | integer | 1 to 200, default 50. |

### Response

```json
{
  "data": [
    {
      "conversation_id": 981,
      "service_id": 42,
      "keyword": "CLINIC",
      "code": "3450",
      "phone": "+2348012345678",
      "unread": 2,
      "last_inbound_at": "2026-10-12T09:32:10+00:00",
      "last_sent_at": "2026-10-12T09:30:40+00:00",
      "last_read_at": null,
      "affinity_active": true,
      "affinity_expires_at": "2026-10-15T09:30:40+00:00",
      "opted_out": false,
      "last_message": {
        "id": "a3c5e8f0-6b1d-4c2e-9f7a-1d2e3f4a5b6c",
        "direction": "inbound",
        "text": "2",
        "created_at": "2026-10-12T09:32:10+00:00"
      }
    }
  ],
  "has_more": false,
  "next_cursor": null,
  "total_unread": 7
}
```

| Field | Description |
|-------|-------------|
| `unread` | Inbound messages since you last [marked it read](#mark-a-conversation-read). |
| `last_inbound_at` / `last_sent_at` / `last_read_at` | Last message from the phone, last message you sent, last time you marked it read. |
| `affinity_active` | `true` while plain replies from this phone route to you (unless another keyword on the code texted it more recently). |
| `affinity_expires_at` | When the window closes: `last_sent_at` plus the window. `null` if you never sent to this phone. |
| `opted_out` | The phone opted out of your keyword or the whole code. Sends to it are refused. |
| `last_message` | The latest message in either direction. |
| `total_unread` | Unread messages across all conversations for this keyword. |

## Get a conversation

```
GET https://sms.esmsafrica.io/v1/two-way/conversations/{phone}
```

Inbound and outbound messages with one phone for a keyword, **oldest first**. Write the
phone in international format; the leading `+` is optional (`2348012345678`), or encode
it as `%2B`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `service_id` / `keyword` | integer / string | Required: which keyword. |
| `code` | string | With `keyword`, when you hold it on two codes. |
| `limit` | integer | 1 to 500, default 100 (the most recent messages). |
| `before` | string | `next_before` from the previous response, to page further back. |

### Response

```json

    "conversation_id": 981,
    "service_id": 42,
    "keyword": "CLINIC",
    "code": "3450",
    "phone": "+2348012345678",
    "unread": 2,
    "last_inbound_at": "2026-10-12T09:32:10+00:00",
    "last_sent_at": "2026-10-12T09:30:40+00:00",
    "last_read_at": null,
    "affinity_active": true,
    "affinity_expires_at": "2026-10-15T09:30:40+00:00",
    "opted_out": false,
    "last_message": { "id": "a3c5e8f0-6b1d-4c2e-9f7a-1d2e3f4a5b6c", "direction": "inbound", "text": "2", "created_at": "2026-10-12T09:32:10+00:00" }
```

Messages have the same fields as [List messages](/docs/api-reference/two-way/messages#list-messages),
plus `auto_reply` (`true` when your keyword's auto-reply sent it). Returns
`404 not_found` when you have never exchanged a message with that phone on this keyword.

## Mark a conversation read

```
POST https://sms.esmsafrica.io/v1/two-way/conversations/{phone}/read
```

Sets `unread` to `0`. It does not change the order of your conversation list. Pass
`service_id` or `keyword` (and `code` if needed) as query parameters.

```json
{ "phone": "+2348012345678", "unread": 0 }
```

<Tab value="cURL">

```bash

  -H "Authorization: Bearer $ESMS_API_KEY"
```

## Service-scoped paths

The same three operations are available under a service ID, which is what the dashboard
uses. They take the same parameters (except `service_id` / `keyword` / `code`) and return
the same shapes.

| Method | Path |
|--------|------|
| `GET` | `/v1/two-way/services/{service_id}/conversations` |
| `GET` | `/v1/two-way/services/{service_id}/conversations/{phone}` |
| `POST` | `/v1/two-way/services/{service_id}/conversations/{phone}/read` |
