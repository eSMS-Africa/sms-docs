## HTTP status codes

| Status | Meaning |
|--------|---------|
| `200` / `201` | Success |
| `400` | Bad request - invalid input, unroutable number, invalid state (e.g. retrying a delivered message) |
| `401` | Unauthorized - missing, invalid or revoked API key / expired session |
| `402` | Payment required - wallet balance too low |
| `403` | Forbidden - insufficient scope, suspended account, sender ID not approved, or recipient opted out |
| `404` | Not found (or not yours) |
| `409` | Conflict - duplicate message or idempotency conflict |
| `413` | Message exceeds the maximum segment count |
| `422` | Request body failed schema validation |
| `429` | Too many requests - rate limit exceeded |
| `500` | Internal server error |

## Error response format

Every error carries a structured `error` object plus the original `detail` field (kept for backward compatibility):

```json
{
  "error": {
    "code": "insufficient_balance",
    "message": "Insufficient balance. Required USD 1.2, available USD 0.5",
    "request_id": "3f9a1c2b4d5e6f708192a3b4c5d6e7f8",
    "details": { "required": 1.2, "available": 0.5 }
  },
  "detail": {
    "code": "insufficient_balance",
    "message": "Insufficient balance. Required USD 1.2, available USD 0.5",
    "required": 1.2,
    "available": 0.5
  }
}
```

Branch on `error.code`. When `detail` is a plain string, `error.code` is the generic code for the status (`bad_request`, `unauthorized`, `not_found`, ...). Validation errors (`422`) use `error.code: "validation_error"` and keep FastAPI's array in `detail`:

```json
{
  "error": { "code": "validation_error", "message": "Request validation failed", "request_id": "...", "details": { "errors": [] } },
  "detail": [
    { "loc": ["body", "to"], "msg": "Field required", "type": "missing" }
  ]
}
```

Every response includes an `X-Request-Id` header (your own value is echoed if you send one). Quote it when contacting support.

## Common error codes

### Send errors

| Code | Status | Description | Resolution |
|------|--------|-------------|------------|
| `bad_request` | 400 | Invalid phone number, no active route for the country, bad `scheduled_at` | Use E.164 format and check [Coverage & Pricing](/docs/help/coverage) |
| `insufficient_balance` | 402 | Wallet balance too low (`required`, `available` in details) | [Top up](/docs/billing/balance) |
| `forbidden` | 403 | Sender ID not approved for this country | Use an [approved sender ID](/docs/sender-ids/request) or omit the field |
| `recipient_opted_out` | 403 | The recipient replied STOP to your messages | Remove the number |
| `account_suspended` | 403 | The account is suspended | Contact support |
| `duplicate_message` | 409 | Identical message to the same number within 5 minutes (duplicate protection on) | Wait, or change the text |
| `message_too_long` | 413 | Message exceeds the segment cap (`max_segments` in details) | Shorten the text |
| `international_price_unset` | 400 | `international: true` but no international price for the country | Send without `international` or contact support |
| `rate_limited` | 429 | Per-key limit exceeded (single send `20/second`, bulk `10/minute`) | Back off and retry |

### Authentication errors

| Code | Status | Description | Resolution |
|------|--------|-------------|------------|
| `unauthorized` | 401 | Key missing, not found or revoked, or session expired | Check the `Authorization: Bearer` header / create a new key |
| `insufficient_scope` | 403 | Key doesn't have the required scope | Create a key with the needed scope |
| `portal_only` | 403 | API keys can only be created or revoked from the dashboard | Use the dashboard |

### Contact list errors

| Code | Status | Description |
|------|--------|-------------|
| `bad_request` | 400 | CSV has no header row or no recognizable phone column |
| `conflict` | 409 | Number already in the list (single-contact add) |

### Retry errors

| Code | Status | Description |
|------|--------|-------------|
| `bad_request` | 400 | Message is not in a failed state, or its route no longer exists |
| `sandbox_no_retry` | 400 | Test (`esms_test_`) messages cannot be retried |
| `insufficient_balance` | 402 | A refunded message is billed again on retry and the balance is too low |

## DLR status codes

These are carrier-level delivery report codes returned in webhook payloads and message timelines.

| DLR Status | Meaning | Message Status |
|------------|---------|---------------|
| `DELIVRD` | Delivered to handset | `delivered` |
| `DELIVERED` | Delivered (alternate format) | `delivered` |
| `ACCEPTD` | Accepted by carrier | `sent` |
| `ENROUTE` | En route to handset | `sent` |
| `ESME_ROK` | Gateway acknowledged | `sent` |
| `UNDELIV` | Undeliverable | `failed` (retried automatically, up to 2 times) |
| `REJECTD` | Rejected by carrier | `failed` (retried automatically) |
| `FAILED` | Generic failure | `failed` (retried automatically) |
| `ESME_RSUBMITFAIL` | Submission failed | `failed` (retried automatically) |
| `EXPIRED` | Message validity expired | `failed` |
| Any other code | Unrecognized carrier status | `failed` |

## Rate limiting

If you exceed the rate limit you receive `429 Too Many Requests` with `error.code: "rate_limited"`. No `Retry-After` header is sent - back off (for example exponentially, starting at one second) and retry. For high-volume use cases, contact support to increase your limits.
